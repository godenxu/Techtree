# 维护手册

本工具的设计目标之一就是**好维护**。绝大多数情况下你只需要动 `data/` 下的文件，不需要看任何一行程序代码。

改完请务必跑一次校验：

```bash
node tools/validate.mjs
```

没有 node 也可以：直接用浏览器打开 `techtree.html`，顶栏右侧会显示校验角标，点开能看到具体是哪个节点出了问题。

---

## 一、新增一个技术节点（5 步）

打开 `data/nodes.js`，在合适的位置粘一个对象进去即可：

```js
{ id:'T6018', name:'向量数据库', en:'Vector Database', cap:'C601', era:'E5', deps:['T6016','T9023'],
  maturity:'mainstream', adoption:'majority', confidence:'high', autonomy:'full', tags:['ai'],
  effort:{manMonth:200,months:9}, value:4, risk:3,
  desc:'面向向量检索的专用存储，支撑 RAG 与相似度召回。',
  unlocks:['语义检索','RAG 知识底座'],
  stack:['Milvus','pgvector'],
  pitfall:'规模不大时用现有数据库的向量扩展即可，不必单独建库' }
```

1. **起 ID**：`T` + 所属能力号 + 两位序号，全局唯一。ID 一旦被别的节点 `deps` 引用，改名就要同步改引用，所以尽量一次起好。
2. **定 `cap`**：填 L1 能力 ID（见 `data/taxonomy.js` 的 `capabilities`）。**这一个字段就决定了它归到哪个领域、哪条 5A 线、在图上落在哪条泳道**，不需要再填 arch 或 domain。
3. **定 `era`**：`E1`–`E6`。规则是它**在行业里成为可落地技术**的时代，不是贵行计划做它的时间。
4. **填 `deps`**：这是最重要的字段。填真正的技术前置——没有它就做不成的那些。**跨 5A 线的依赖尤其要填全**，那是本图价值最大的部分。
5. **跑校验**。校验器会查：ID 重复、依赖指向不存在的节点、时代倒挂（依赖了更晚时代的节点）、循环依赖、枚举值非法。

上层的领域图、能力图、连线、进度、路线图**全部会自动跟着变**，不需要任何额外操作。

### 字段完整规范

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | 唯一标识 |
| `name` / `en` | `name` ✔ | 中英文名 |
| `cap` | ✔ | L1 能力 ID，决定归属 |
| `era` | ✔ | `E1`–`E6` |
| `deps` | ✔ | 前置节点 ID 数组，可为空 `[]` |
| `maturity` | ✔ | `mature` 成熟期 / `mainstream` 主流期 / `early` 早期采用 / `emerging` 萌芽期 / `experimental` 实验期 |
| `adoption` | ✔ | `universal` 普遍具备 / `majority` 多数在建或已建 / `leaders` 领先机构具备 / `pilot` 个别试点 / `none` 尚无规模落地 |
| `confidence` | ✔ | `high` / `medium` / `low`。`low` 会在界面上标灰提示「待核实」 |
| `autonomy` | ✔ | `full` 已全栈适配 / `partial` 部分适配 / `dependent` 依赖国外 / `na` 不涉及 |
| `tags` | ✔ | 专题标签数组，可为空。现有：`ai` `xinchuang` `risk` `open` `realtime` |
| `effort` | ✔ | `{manMonth, months}`，行业基准参考值，路线图的产能装箱靠它 |
| `value` / `risk` | ✔ | 1–5 |
| `desc` | ✔ | 一句话定位 |
| `unlocks` | | 解锁能力数组，文明风格的收益描述 |
| `stack` | | 主流技术选型参考 |
| `pitfall` | | 常见坑，会在详情面板显示为醒目提示 |

### 删除或改名节点

删之前先搜一下有没有别的节点 `deps` 引用它。直接删会被校验器抓到（`依赖了不存在的节点`），按提示改就行。

## 二、新增一个专题标签

比如想加一个「绿色金融视图」：

1. 在 `data/taxonomy.js` 的 `tags` 数组加一项：
   ```js
   { id:'green', name:'绿色金融视图', color:'#34d399', desc:'ESG 与绿色金融相关节点' }
   ```
2. 给相关节点的 `tags` 加上 `'green'`。

顶栏「专题」下拉会自动出现新选项，选中后图上只留带该标签的节点，**被隐藏节点的依赖链会自动穿透收缩**（A→隐藏→B 会画成 A→B），链条不会断。

> 记住一条原则：**结构维度只能有一个（5A），标签维度可以有任意多个**。想让一个节点"同时属于两条线"时，正确做法是打标签，而不是改结构——改结构会把 DAG 弄乱。

## 三、新增一个单位（3 步）

1. 复制 `data/orgs/_template.js` 为 `data/orgs/<你的单位ID>.js`
2. 打开新文件，填 `orgId`（与文件名一致）、`orgName`、`orgType`，然后在 `overrides` 里写状态
3. 在 `data/orgs/index.js` 的 `TT.orgRegistry` 数组里加一行：
   ```js
   { id: 'branch-sh', name: '上海分行', file: 'data/orgs/branch-sh.js' }
   ```

不需要改 `techtree.html`，也不需要改任何代码。

### 单位档案的核心原则：只写覆盖值

```js
overrides: {
  'T7023': { status:'building', owner:'数据管理部', start:'2025-03', target:'2026-12',
             note:'一期标签体系已投产，二期实时能力建设中' },
  'T4021': { status:'built', actualEffort:4200 }
}
```

**没写的字段一律继承基准树。** 所以当基准树日后新增技术节点时，各单位档案**一行都不用改**，新节点会自动以「未评估」出现在每个单位的视图里，顶栏还能看到填报进度。

可覆盖字段：`status` `autonomy` `owner` `start` `target` `actualEffort` `note`，以及节点的任意其他字段。

`status` 取值：`built` 已建成 / `building` 建设中 / `planned` 规划中 / `none` 未启动 / `na` 不适用 / `unknown` 未评估。

### 本单位特有的自研系统

写进该单位档案的 `customNodes`，字段与 `data/nodes.js` 的节点完全一致，`deps` 可以引用基准树的节点 ID。它只会出现在这个单位的视图里，在图上带「本单位自建」标记。

## 四、不想手写 JS？三条更省事的路

### A. 页面里改，改完导出

1. 顶栏点「维护」进入维护模式
2. 切到目标单位 → 点节点 → 右侧面板直接改状态、责任部门、时间、备注
3. 顶栏「导出」→「本单位档案 JSON」→ 下载得到 `<orgId>.js` → 覆盖 `data/orgs/<orgId>.js`

改基准树的节点内容同理，导出「节点数据文件 nodes.js」覆盖 `data/nodes.js`。

### B. Excel 里改

顶栏「导出」→「节点清单 CSV」，得到的 CSV 是 UTF-8 带 BOM 的，**Excel 双击直接能开**，一行一个节点。批量编辑完再按上面的字段规范回填即可。

### C. 只想看不想改

什么都不用做，默认的世界基准视图本身就是一张可以直接汇报的行业全景图。

## 五、打包成单文件

需要发邮件或丢到没有目录结构的地方时：

```bash
python3 tools/build.py
```

会在 `dist/techtree-standalone.html` 生成一个把所有 CSS / JS / 数据内联进去的单文件。只用 Python 标准库，不需要 node 和 npm。

**注意**：单文件版本是快照，之后再改 `data/` 需要重新打包。日常维护还是用拆分版本更方便。

## 六、常见问题

**双击打开是空白页？**
确认 `techtree.html` 和 `data/`、`assets/` 三者在同一个目录下、相对位置没变。本工具用 `<script src>` 加载数据而不是 `fetch`，正是为了绕开 `file://` 的 CORS 限制——但目录结构被打散就不行了。

**改了 nodes.js 没生效？**
浏览器缓存。Ctrl+F5 强制刷新。

**顶栏出现红色「数据错误」角标？**
点它，会列出具体是哪个节点的什么问题。红色错误必须修（会影响图的正确性），黄色警告可以按需忽略（比如「跨代较远」通常是合理的长跨度依赖）。

**节点太多看不过来？**
这正是三层颗粒度存在的意义。日常汇报停在「领域」层，需要细看时双击展开单个领域即可，不必整图切到技术层。
还可以点顶部的 A1–A5 进度格只看某一条架构线（可多选），或用「专题」下拉抽取 AI / 信创 / 风控等子树。

**为什么同一个领域在图上出现好几次？**
聚合层按「领域 × 时代」切分，一个领域在它有技术节点的每个时代各出现一格。
这样六个时代在任何粒度下都完整可见——否则早期和末期的时代会整列消失，讲演进时直接断代。
详见 `docs/设计说明.md`。

**怎么收拢已经展开的节点？**
双击展开层里的技术节点会收拢它所属的能力格，再双击一次收回领域格；
Esc 逐级收起；点面包屑的「全景」一次性收全。
